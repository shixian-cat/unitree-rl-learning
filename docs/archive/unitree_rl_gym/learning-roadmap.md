# RL 学习路线：Unitree 腿式机器人

## 目标

在没有真机的前提下，完成一次可复现的腿式机器人强化学习练习：读懂 Go2 任务配置、运行预训练策略、短训 PPO、做一个单因素对比，并将策略放入 MuJoCo 做 Sim2Sim 检查。

## 阶段 0：准备概念

先理解 MDP、状态/观测、动作、奖励、episode、策略、价值函数、PPO、并行采样。当前重点是把概念对应到代码，而不是先追求完整数学推导。

交付物：一页笔记，解释每个概念在 Go2 locomotion 环境中分别对应什么。

## 阶段 1：读懂仓库

使用官方仓库：<https://github.com/unitreerobotics/unitree_rl_gym>。先选 Go2，依次追踪：

1. `legged_gym/scripts/play.py` 如何加载策略；
2. Go2 task/config 如何定义观测、动作、奖励、终止条件和随机化；
3. `train.py` 如何创建环境并启动 PPO；
4. checkpoint 如何保存和导出；
5. `deploy/deploy_mujoco/` 如何载入导出的策略。

交付物：一张数据流图 `观测 → 策略 → 动作 → 仿真 → 奖励/新观测`，以及对 reward 各项的简短说明。

## 阶段 2：先回放，再训练

先按官方说明运行已有策略的 `play`，确认模型、配置和仿真环境工作。然后运行短训练，检查日志、checkpoint 和回放结果。第一次训练只需验证流程，环境数量和迭代数先用较小配置。

每次记录代码 commit、配置、随机种子、并行环境数、迭代数、训练耗时、结果和异常。

交付物：baseline 实验记录及至少一个可加载 checkpoint。

## 阶段 3：单因素实验

提出一个可检验的问题，例如“提高速度跟踪奖励权重是否提升速度跟踪，但增加能耗或不稳定？”每个实验只改变一个因素。至少比较训练曲线和若干回放片段；如果预算允许，换随机种子复现。

交付物：一张对比表和一段解释，区分观察到的结果与推测原因。

## 阶段 4：Sim2Sim

把训练导出的策略放到仓库的 MuJoCo 部署路径。检查控制频率、关节顺序、动作缩放、观测归一化、初始姿态和模型配置。记录跨模拟器差异及其可能来源。

交付物：Sim2Sim 检查记录。没有真机仍可完成这一阶段。

## 阶段 5：扩展问题

基础流程跑通后，再研究 domain randomization、地形泛化、动作参考/模仿学习、恢复策略、策略鲁棒性或更现代的 Isaac Lab 工作流。不要同时更换仿真器、算法和机器人任务，否则难以归因结果。

## 数据来源应该怎么选

- **仿真交互数据：**标准 PPO locomotion 的主要数据来源。策略与物理仿真反复交互，样本由训练过程产生。
- **真机数据：**当前不是必需项；后续用于标定、真实评估、故障分析和 sim-to-real 研究。
- **通用视频：**对基础 PPO locomotion 不是直接训练输入；通常用于视觉表征、VLA 或世界模型。
- **示范/合成轨迹：**用于模仿学习、参考动作、奖励构造或初始化等扩展方法；不要误认为纯 PPO 跟练的前置依赖。

## 每次实验的基本规范

1. 先写假设和唯一改动；
2. 固定并记录种子及配置；
3. 保存代码 commit、日志、checkpoint；
4. 检查训练指标之外的回放行为；
5. 失败时记录复现方式和证据；
6. 不把仿真成功表述成真机验证。
